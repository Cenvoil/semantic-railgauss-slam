## §1 「本方法」的定义（缺一不可）

### 1.1 结论（对外表述用这一句）

> **本方法 = 我们自己在 SGS-SLAM 基线上改造的实现**，即：  
> SGS-SLAM 官方多通道优化主干（损失权重与官方一致）
>
> - 场景适配开关层（V4 系列 30 个环境变量）
> - RGB 单目深度估计 + LiDAR 尺度锚定
> - 标注 SAM 级掩膜 + SegFormer 填充推理
> - INS 初始化
> - 轨道先验
> - 天空掩码

**除数据集本身残缺外，凡不满足上述全部条件者，不得称为「本方法」**，只能称「基线」「消融配置 X」或「官方 SGS-SLAM」。

### 1.2 逐项定义与验收标准

| #  | 组成项                | 含义                                                       | 验收标准（怎么算「有」）                                                                | 缺失时的后果                               |
| -- | ------------------ | -------------------------------------------------------- | --------------------------------------------------------------------------- | ------------------------------------ |
| A1 | **SGS-SLAM 主干**    | 官方 ECCV 2024 多通道（im/depth/seg）优化框架                       | `loss_weights` = tracking `im0.5 / depth1.0 / seg0.05`，**与官方 Replica 逐位一致** | 不是本方法，是别的系统                          |
| A2 | **V4 系列改造开关**      | 场景适配层：天空(7)/几何掩膜(4)/深度门控(4)/前表面(2)/远场正则(4)/初始化像素(4)/各向异性 | `scripts/slam.py` 内 `V4_*` 环境变量**30 个**；官方 `os.environ` 计数 = **0**          | 退化到官方原版行为                            |
| A3 | **RGB 单目深度估计**     | 对输入 RGB 做单目深度估计（非 LiDAR 投影）                              | `output_1.0_mono` holdout **absrel = 0.4621**                               | KITTI 上 95.6% 像素深度=0 → tracking 收敛失败 |
| A4 | **LiDAR 尺度锚定**     | 用 LiDAR 对单目深度做尺度标定                                       | `output_1.0_v4np` holdout **absrel = 0.0293**（较 A3 **降 16 倍**）              | 尺度漂移，ATE 差一个量级                       |
| A5 | **标注 SAM 级掩膜**     | 标注升级到实例级/SAM 级掩膜（而非 2D 框）                                | 掩膜落盘且参与 `semantic_ids` 写入                                                   | 语义退化为框级                              |
| A6 | **SegFormer 填充推理** | 用 SegFormer 对掩膜外区域做语义填充推理                                | 有独立 SegFormer 推理产物 + 类别回填                                                   | 掩膜外区域语义空洞                            |
| A7 | **INS 初始化**        | 用 INS/GNSS 位姿做逐帧位姿初始化                                    | `tracking.ins_init=True` 且 `traj.txt` 喂的是**真实 INS/GNSS 序列**                 | ⚠ **本方法最大短板**：无INS 时定位会崩（见 §3）       |
| A8 | **轨道先验**           | 轨道几何先验（只罚垂距，沿轨滑动无梯度）                                     | `RAIL_PRIOR` 开关；**直线序列上必然中性，只有弯道才有梯度**                                      | 直线场景无变化（中性≠失效）                       |
| A9 | **天空掩码**           | 天空区域掩码，排除天空深度/语义异常                                       | V4 天空开关组（7 个）生效                                                             | 天空深度污染单目估计                           |

### 1.3 ⛔ 例外条款（唯一允许缺项的情形）

> **仅当目标数据集「完全没有 INS 数据」时，A7（INS 初始化）允许缺失。**

- 缺失后必须：
  1. 在所有对外表格中显式标注 `INS: 无（数据集不含）`；
  2. 不得用「用评测真值当 INS」的方式变相补齐（见 §2 铁律）；
  3. 该配置的所有精度指标须标为**独立配置**，不得与 OSDaR 上的数字直接并列。

**该条款只对 A7 有效。A2/A3/A4/A5/A6/A9 一律不可豁免。**

## §2 ATE 基线约束（本方法在 KITTI 上应达到 10 cm 级）

### 2.1 约束条文

> **本方法在 KITTI 数据集上的 ATE 已能达到 10 cm 级误差。  
> 若后续出现「异常偏大」的情况（量级 ≫10 cm，例如几十 cm 到数十 m），  
> 一定是自己写的脚本或坐标换算关系出了问题，而不是方法能力不行。**

**处置流程（禁止跳步）**：一旦观测到 ATE 异常偏大，  
**必须先按§2.3 清单逐条自查并给出排除证据**，才允许讨论「方法在车载场景失效」这一结论。

### 2.2 为什么立这条（历史代价）

10-09 当天在 KITTI 上先后出现两个**假失效**，都被自查抓出：

| 假象                                               | 真实原因                                          | 抓到的方式                                        |
| ------------------------------------------------ | --------------------------------------------- | -------------------------------------------- |
| ATE **5275.34 cm**、RTE **65.434%**               | 根因=**深度只有 4.38% 有效像素** + 无INS 初始化，两者叠加        | 补深度估计 + `odom_init` 后 → **45.17 cm**（降 117×） |
| ATE **6394 cm**、里程 **567 m vs 真值 231 m**（2.45 倍） | 把 w2c 的 `t` 当成相机中心 `C`                        | 用 KITTI 官方 poses 交叉验证 ⇒ 正确口径 **2.98 cm**     |
| ATE **2577 cm**                                  | KITTI `poses.txt` 是**行主序 3×4**，误读成 `G[:,3:6]` | 核对首帧真值应为 `[0,0,0]`                           |

⇒ **这三次都是"脚本/换算"问题，不是方法问题。** 所以本条约束是**有实证依据的**，不是空话。

### 2.3 ATE 异常偏大时的自查清单（逐条给证据才���往下走）

| #  | 自查项                              | 判据 / 方法                                                                                |
| -- | -------------------------------- | -------------------------------------------------------------------------------------- |
| 1  | **w2c t vs 相机中心 C 用混了吗**         | 项目 `evaluate_ate` 取两边 `traj[:3,3]`，**两侧都是 w2c 的 t**。⚠ `traj.txt` 第 3 列是**相机中心 C**，不是 t |
| 2  | **quad 顺序是 wxyz 还是 xyzw**        | `cam_unnorm_rots` = **wxyz**（与 GT 旋转中位差 0.015；按 xyzw 解读差 2.00≈180°翻转）                  |
| 3  | **`poses.txt` 行主序 3×4 读对了吗**     | 平移在 `reshape(3,4)[:,3]`，**不是 `G[:,3:6]`**                                              |
| 4  | **`inv(pose)` 方向对吗**             | w2c 与 c2w 互逆；`C = −R^T@t` 的**负号不可省**（漏负号：5.09 cm → 19170 cm）                           |
| 5  | **用了独立第三方数据交叉验证吗**               | ⛔ 无交叉验证的 ATE 数字一律不采信（铁律⑱）。KITTI 可用官方 `poses/*.txt`                                     |
| 6  | **深度有效像素占比**                     | 必须 100%（`float32 .npy`）。若像旧 `kitti_ds` 只有 **4.38%** ⇒ 先补深度估计，别急着下结论                    |
| 7  | **初始化是否合法**                      | `ins_init` 喂的必须是**真实 INS/GNSS**，不能是评测真值（见 §2.4）                                        |
| 8  | **帧数是否越界读零**                     | 有效帧必须「位移非零」计数；否则里程比 ≈0.38，看着像崩溃实为越界                                                    |
| 9  | **口径三件套**                        | 帧数 / 分辨率 / 评分数，跨 run 比对前先核（铁律⑬）                                                        |
| 10 | **`regression_test_ate.py` 过了吗** | 口径地基自检，**每次必跑**，PASS 才允许采信新数字                                                          |

### 2.4⛔ 绝对红线：真值当先验 = 测试集泄漏

- `ins_init=True` 喂的 `traj.txt` 若**就是评测真值** ⇒ 每帧 tracking 从真值起步  
  ⇒ 该 ATE 衡量的是「从真值出发能优化回多远」，**不是定位精度**。
- 实证：`cam_trans` 与真值 w2c t 在 f0/f1 **diff = 0.0000（逐位相同）**，全程均值 0.0509 m。
- ⚠ `use_gt_poses=False` **挡不住** `ins_init`（与该标志无关）。
- ⇒ ★★ **KITTI 上不做任何外部先验**（Gary 2026-10-10 拍板，**`odom_init` 一律不做**）。  
  理由三条：① 违背「本方法」九项定义（§1.2）；  
  ② 论文表述会从「我们的方法达到 X」变成「我们的方法 + KISS-ICP 先验达到 X」，定位精度不再是自己能力；  
  ③ KISS-ICP 成了我们的零件供应商，与 KISS 的横向对比变成同门 competition、口径不干净。  
- ⇒ ★★ **本方法在 KITTI 上唯一的合法配置**：  
  `ins_init=False`（KITTI 无 INS，按 §1.3 例外条款标注 `INS:无`）  
  + 稠密单目深度 + LiDAR 尺度锚定 + 天空掩码 + 轨道先验，  
  **定位精度必须由本方法自己算出**。`slam.py` 保持 md5 `76532b2c`（1787 行，无 odom_init）。  
- ⚠ **历史混淆点**：1.2 的 `traj.txt` 是**真实 INS 序列**（合法），  
  我们自建的 `kitti_ds/*/traj.txt` 是**官方评测真值**（泄漏）。  
  **同一个文件角色完全不同，跨数据集搬开关前必须核实（铁律⑲）。**

### 2.5 ★ KITTI 的 IMU/INS 数据（2026-10-09 核实，**按 Gary 判断不作为泄漏约束**）

**官方 odometry 包里没有 IMU/INS/OXTS**（S3 实测 `imu`/`ins`/`oxts` 全 404），
官方只提供 5 个包：`velodyne` / `calib` / `poses` / `color` / `gray`（+ devkit）。

## §3 横向对比目标（为什么做 KITTI）

### 3.1 现状问题

1. 本方法在 **OSDaR23 的 1.2 序列**上已达良好水平，但**从未做切换数据集验证**；
2. **从未与其他 SLAM 系统做过同一数据集上的对比**；
3. 受限于 OSDaR23 数据集本身，**可跑出 SLAM 指标的第三方系统极少**（全网仅 ORB-SLAM2、KISS-ICP  
   两篇报了 OSDaR23 的 SLAM 数字，**GS 类方法一个都没跑过**）。

### 3.2 第一步：迁移到 KITTI

**目标（两条，缺一不可）**：

1. **定位本方法在众多 SLAM 系统中的水平** —— 在定位精度（ATE/RTE）与其他指标（PSNR/mIoU）上，  
   本方法处于什么档位；
2. **寻找"水平相当但稍差"的 SLAM 系统实跑对比** —— 作为论文素材。  
   （候选：KISS-ICP、CT-ICP、SAGE-ICP、IMLS-SLAM、MULLS、SuMa++、SA-LOAM、LOAM、F-LOAM；  
   标注为不可比的：ORB-SLAM2/3、LIO-SAM/FAST-LIO2、LeGO-LOAM、R3LAM 等）

### 3.3 ⚠ KITTI 口径三条硬约束（先记住，会省掉一整天）

| 约束                                | 内容                                                                                                                                                                         |
| --------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **① 榜单是 11-21 测试集口径，不是 00-10**    | 铁证：KISS-ICP 论文 `00-10=0.50 / 11-21=0.61`，榜单值= **0.61**。⇒ **11-21 无公开真值 ⇒「跑 22 序列和榜单比」方法论上不成立**。正确做法：**跑 00-10，与论文里的 00-10 数字比**                                            |
| **② KITTI 官方唯一指标是 RTE，榜单上没有 ATE** | RTE = 所有长度 (100..800) m 子序列误差平均，translation **%** + rotation **deg/m**。⚠ 段误差前**必须先 SE(3) 对齐**（KISS 世界系=首帧 LiDAR 系，GT=cam0 系），不对齐 seq05 报 114.3%、对齐后 1.441%。★ **此错不会让自检失败** |
| **③ ATE 必须双口径落档**                 | **w2c-t**（内部/OSDaR 对用）+ **相机中心 C**（KITTI 社区对比用，《A Chef's KISS》报的 KISS ATE-3D 1.83 m 就是社区口径）。⚠ 长序列上 w2c-t 系统性更悲观（seq00 全序列 514.00 vs 356.72 cm）。**RTE 不受影响**（段内相对量，天然抗累积）   |

★ **最佳文献锚点 = SAGE-ICP 论文 Table II**（arXiv:**2310.07237**，浙大 2023-10）：  
同为 00-10 逐序列 t_rel(%)。⚠ `2203.06812` 是**错的**（纯数学论文）。

## §4 指标台账规则（配合 `KITTI_横向对比_指标台账.xlsx`）

### 4.1 四指标

| 指标       | 单位       | 本项目口径               | 说明                                                   |
| -------- | -------- | ------------------- | ---------------------------------------------------- |
| **ATE**  | cm       | ⛔ **一律用 w2c 的 `t`** | SE(3) 对齐、逐点误差**均值**（非 RMS）。⚠ 引���必写「w2c-t」           |
| **RTE**  | %（t_rel） | KITTI 官方口径          | 段长 (100..800) m、first 步长 10、段末按 GT 距离选、除以**标称 L**    |
| **PSNR** | dB       | 项目 `evaluate`       | ⚠ **KITTI 榜单无任何图像指标**，官方亦未定义 PSNR 协议 ⇒ 各论文自定义**不可比** |
| **mIoU** | —        | 项目语义评测              | ⚠ 需声明语义类别映射口径                                        |

### 4.2 填「/」的规则（不是填「N/A」，也不是留空）

填 `/` 的四种情形，**每种都要在备注里写明属于哪一种**：

| 情形          | 说明                                                                |
| ----------- | ----------------------------------------------------------------- |
| `/ = 无此指标`  | 该方法根本不产出该指标（例：KISS-ICP **无渲染分支、不读图像、不处理语义** ⇒ PSNR 与 mIoU 均填 `/`） |
| `/ = 口径不可比` | 有数字但协议不同（例：KITTI 榜单无 PSNR 协议 ⇒ 第三方 PSNR 全填 `/`）                   |
| `/ = 未跑`    | 该方法尚未实跑（待补）                                                       |
| `/ = 无有效真值` | 该序列无公开真值（例：KITTI 11-21）                                           |

### 4.3 台账维护规则

1. **数字只能来自实际执行**（铁律③）；外来的写进 `来源` 列并注明出处（论文/榜单/实测）；
2. 跨口径比较必须**同集合 + 同协议**（帧数/分辨率/评分数三项先核，铁律⑬）；
3. ATE 引用**必须带口径标签**（`w2c-t` 或 `camcenter`）+ 是否 `ins_init`/`odom_init`；
4. 表格中 **OSDaR 数字与 KITTI 数字不可直接相减**（1.2 是 21 m 铁路直线，KITTI 00 是 3724 m  
   城市道路网，直线性 1.0000 vs 0.026，长度差 176 倍）⇒ 横向对比只能在各数据集**内部**做，  
   或用 **ATE/里程** 的相对比例。
