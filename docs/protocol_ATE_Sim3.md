# ATE 口径：新增 Sim(3) 对齐报告（含尺度）· 2026-09-21

> **一句话结论**：冻结基线 `d8_full75` 的 ATE，在**现行口径（Horn 对齐、不含尺度）下是 23.45 cm**；
> 换成**Sim(3) 对齐（同时对 1 个尺度求解）后是 2.80 cm**，差 **8.4 倍**。
> 也就是说，那 23.45 cm 里约 **88% 是"整体尺度差"**，不是轨迹形状错。
> 本改动**只增加一个报告口径**，不碰数据、不碰代码、不碰任何已完成的 run、不解冻基线。

---

## 0 先说这是不是"改尺子作弊"

不是放宽，而是**回到单目 SLAM 的常规做法**，并且**两个数都留档、主推哪个由你定**。

- 单目 + 深度监督的 SLAM，**世界尺度是由输入深度的绝对量级定义的**（本项目已实测：把深度整体乘 c，
  估计轨迹里程就精确乘 c —— ×1.5→×1.49、×2.0→×1.98、×2.37→×2.37）。尺度本身不是这个系统"学"出来的。
- 因此用**不含尺度**的 SE(3) 对齐去衡量它，等于把"深度源的尺度偏差"全额记成"轨迹误差"。
  本项目实测：基线路径 20.33 m vs 官方 21.16 m，只差 **4.1%**，但这就是 23.45 cm 的主要来源。
- 反过来，Sim(3) 不等于"什么都放过"：`d8_fullA` 的 Sim(3) 仍是 **36.25 cm**（它的几何确实错了），
  而只差尺度的 `ga15/ga2` 都掉到 3~5 cm。**所以 Sim(3) 比 SE(3) 更能区分"尺度偏"和"几何坏"。**

## 1 源码级口径定义（两套的唯一差别就是"解不解尺度"）

`SGS-SLAM/utils/eval_helpers.py::evaluate_ate` → `align(model=官方轨迹, data=估计轨迹)`：

```
转成 (3,N) 平移列  →  Horn 闭式对齐（SVD）  →  逐帧平移残差 r_i  →  返回 r_i 的【均值】
```

⚠ 三个容易踩的点（都已核对）：
1. **返回的是均值，不是 RMS**，虽然打印叫 `Final Average ATE RMSE`。
   （`scale_diag.py` 用的是 RMS，所以它给基线的 26.46 与日志的 23.45 不冲突，差在均值/均方根。）
2. **对齐不含尺度**：`align()` 只解 R、t。这就是本文要改的那一点。
3. 第 0 帧用 `first_frame_w2c`（= 数据集第 0 帧位姿的逆），其余帧用 `cam_trans`；GT 为 NaN 的帧跳过。

**Sim(3) 口径**：把 `align()` 扩展成同时解一个最优标量 s（Umeyama），
即最小化 `|| s·R·X_c − Y_c ||²`，闭式解 `s = trace(D·S) / ||X_c||_F²`，
**之后残差仍然按原口径取均值**。除 s 之外的一切（帧集合、方向、均值）逐位不变。

  → 两条独立路径互相验证，Sim(3) 解出的尺度就是"里程比"。

## 3 自检与交叉验证（脚本自带，输出已核对）

1. **口径复刻自检**：`SE(3)-mean` 一列必须等于各 run 日志里的 `Final Average ATE RMSE`。
   实测逐 run 精确相等（23.45 / 22.81 / 231.16 / 22.15 …）→ **复刻成功**。
2. **一致性自检**：把估计轨迹整体乘 `s*` 后再做 SE(3) 对齐，其均值必须等于 Sim(3) 的均值。
   实测 8 个 run **差值全部为 ±0.00 cm** → Sim(3) 实现正确。
3. **f 扫描交叉验证**（与既有 `scale_diag.py` 同法）：逐尺度重对齐求最小 ATE，落在同一邻域
   （基线 2.97 cm @f=1.045 vs Sim(3) 2.80 cm @s\*=1.043）。
   差 0.17 cm 的原因是**两个准则不同**：Umeyama 最小化**平方和**，f 扫描最小化**均值**，
   两者的最优点不严格重合，且均值函数在最优附近有尖角、网格取不到精确点。**Sim(3)（2.80）是精确最优值。**

## 6 附：本脚本实现时踩的一个坑（写下来防复发）

Sim(3) 的最优尺度是 `s = trace(D·S) / ||X_c||_F²`，**分母是 Frobenius 范数平方（对所有元素求和），
不能再除以 N**。第一版写成 `sum/N`，结果 `s* = 104`（≈ 帧数 100）、Sim(3)-ATE 算成 **542 m**，
而 SE(3) 那一列照样是 23.45 —— 也就是**自检 1 通过、但数字明显荒谬**。
→ 教训：**自检要覆盖每一个新量**，不能只验"旧口径没被改坏"。
